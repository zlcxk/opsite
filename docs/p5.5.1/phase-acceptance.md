# P5.5.1 标准化知识建档与自动文档初始化 · 阶段验收

> 说明：本次收到的 PRD 在 `### 12.2 建档流程` 处截断，12.2 之后的要求不可见。本阶段按已提供的章节实现；未收到的后续验收条目未做主观补充，已在「未覆盖与限制」中说明。

## 1. 交付范围

- 五套固定模板：`component-l2-v1`、`concept-l2-v1`、`protocol-l2-v1`、`resource-l2-v1`、`practice-l2-v1`。
- 四类手动范围：软件、技术节点、软件 + 节点组合、新建知识。
- 预览 → 确认 → 执行的两阶段流程，执行必须携带与当前请求一致的预览哈希。
- 自动规则：软件创建、节点创建两类触发；规则持久化，可暂停、删除、查看最近运行状态。
- 无法安全决策的自动任务写入“待处理建档项”，不猜测领域、父节点或关联方式。
- 官方来源管理与 HTTPS 链接检查（SSRF 防护、超时、大小、并发、重定向再校验）。
- 知识 Linter：结构、长度、版本、来源、占位提示、内容来源、关联、软件关联、验证状态。
- 统一 UI 入口“知识建档”，并从软件详情、技术节点详情深链进入。
- 复用既有技术节点、文档、关联表；未新增第二套知识存储，仅新增规则表与待处理表。

## 2. 数据模型

新增两张表，均使用 SQLite，迁移语句为 `CREATE TABLE IF NOT EXISTS`：

### `tech_knowledge_build_rules`

| 字段 | 用途 |
| --- | --- |
| `id` | UUID |
| `name` | 规则名称 |
| `enabled` | 启用 / 暂停 |
| `target_type` | `software` / `node` / `combined` |
| `trigger_type` | `software_created` / `node_created` |
| `scope_type` | 与手动建档一致的范围类型 |
| `scope_config` | 分类、领域、节点类型等筛选（JSON） |
| `mapping_config` | 目标领域、父节点、节点类型、关联策略、名称模板（JSON） |
| `template_key` | 固定模板键 |
| `source_config` | 官方文档与参考来源（JSON） |
| `last_run_at` / `last_run_status` / `last_error` | 可追溯的运行记录 |
| `created_at` / `updated_at` | 时间戳 |

### `tech_knowledge_build_pending`

记录自动规则无法安全决定的项：`rule_id`、`source_type`、`source_id`、`name`、`reason`、`payload`、`status`、时间戳。同一规则、同一来源只保留一条 `pending` 记录。

索引：

- `idx_tech_build_rules_trigger(enabled, trigger_type)`
- `idx_tech_build_pending_status(status, created_at DESC)`

## 3. 模板

固定章节与顺序：

1. 技术定位
2. 设计原理
3. 工作机制
4. 关键配置与实践
5. 版本差异与兼容性
6. 常见问题与限制
7. 技术关联
8. 参考资料

每套模板有独立写作提示，提示以 HTML 注释保存，不会渲染成正文。模板只写入已知结构化信息（名称、类型、分类、安装版本、上游最新版本、描述、来源链接等），不生成技术结论。

版本章节固定呈现四个维度：

| 版本维度 | 当前记录 |
| --- | --- |
| 安装 / 使用版本 | 来自软件 `currentVersion`（若存在） |
| 上游最新版本 | 来自软件 `latestVersion`（仅展示，不写入适用版本） |
| 文档适用版本 | 待核实，未写入 `applicableVersions` |
| 本文实际核实版本 | 未核实 |

初始化文档始终为 `draft`，不会写入 `applicableVersions`，也不会自动验证。

## 4. 预览与执行

- 软件、节点、组合范围必须提供显式条件（ID、分类、领域、父节点、节点类型或筛选），否则返回 400：
  - `软件范围必须明确选择软件、分类或筛选条件，不能默认全量执行`
  - `节点范围必须明确选择节点、领域、父节点或类型，不能默认全量执行`
- 前端默认不预选“全部软件 / 全部节点”，必须由用户主动选择。
- 预览返回：计数（软件、节点、新建、关联、初始化、跳过、待人工、缺少官方来源）和逐项结果。
- 执行要求 `confirmed: true` 且 `previewHash` 与当前请求一致；否则拒绝：
  - `执行前必须确认预览范围`
  - `预览已变化，请重新预览后再执行`
- 结果分为：已创建、已关联、已初始化、已跳过、待补充、失败。
- 每个条目使用独立事务；单条失败不会影响其他条目，也不会留下半完成的关联。

### 安全不变量

- `skipExistingBody` 在服务端强制为 `true`，不受请求控制。
- 已有 Markdown 正文一律跳过；初始化 SQL 额外带 `content_markdown IS NULL OR TRIM(...) = ''` 条件。
- 不修改 `personalNotes`、`researchQuestions`。
- 不自动把 `draft` 改为 `complete`；执行只写 `draft`。
- 已验证或已完善的节点默认跳过。
- 同名节点不自动合并：改为 `pending`，由人工决定。
- 重复执行幂等：同一文档已有正文时第二次执行只产生“已跳过”。
- 软件关联使用 `ON CONFLICT(node_id, software_id) DO NOTHING`。
- 仅处理活跃节点 / 软件，默认跳过归档。

支持的筛选：仅无文档、仅草稿、跳过已有正文（强制）、跳过已验证、排除软件 ID、排除节点 ID、仅活跃、跳过归档。

## 5. 自动规则

- 触发点位于路由层：软件创建成功后调用 `runKnowledgeBuildRules('software_created')`，节点创建成功后调用 `runKnowledgeBuildRules('node_created')`。
- 规则执行失败不会影响软件 / 节点创建本身，只记录 `last_run_status = failed` 与 `last_error`。
- 规则未启用时不参与运行。
- 目标领域、父节点缺失，同名节点冲突，或关联策略无法确定时，写入待处理表；UI 可跳转到手动建档并忽略该待办。
- 未提供“默认对所有软件启用自动建档”的全局开关或默认规则。

## 6. 官方来源与 URL 检查

- 只允许 HTTPS；拒绝带用户名 / 密码、非 443 端口的 URL。
- 拒绝 `localhost`、`.localhost`、`.local`、`.internal`、`metadata`、`metadata.google.internal`。
- DNS 解析后校验全部地址；禁止：
  - IPv4 私网、环回、链路本地、保留、组播、云元数据段；
  - IPv6 环回、ULA、链路本地、站点本地、组播；
  - IPv4 映射、IPv4 兼容、NAT64、6to4、Teredo、文档保留段。
- 请求使用已验证地址做 DNS pinning，防止解析后重绑定。
- 最多 3 次重定向；每次跳转前重新执行完整地址校验，防止重定向绕过。
- 单次请求 8 秒超时，响应最多读取 256 KB，默认并发 4、上限 8。
- 不可访问的链接保留在资料记录中，并提示“不得标记为已核实”；不会伪装成已验证。

## 7. 知识 Linter

检查项：

- 正文非空；
- 八个固定章节齐全且顺序正确；
- L2 文档至少 1,500 字符；
- 版本章节存在，适用版本未核实或缺失时给出警告；
- `applicableVersions` 不得写成最新 / `latest`；
- 至少两个 HTTPS 官方来源，来源格式合法；
- 无“待补充 / 待核实 / TODO / TBD / 请填写”等占位残留；
- 已标注内容来源；
- 有技术关联，或正文给出独立说明；
- 组件节点应关联软件；
- 状态为 `complete` 时必须有验证版本与验证时间；
- 可选检查来源可达性。

结果状态为 `pass` / `warning` / `fail`。Linter 只读，不修改 `contentStatus`，全部通过也不会自动标记为已完善。技术节点详情页提供“文档体检”入口。

## 8. UI

- `/tech/build`：手动建档与自动规则两个模式。
- 技术地图页头新增“知识建档”。
- 软件详情“关联技术知识”面板新增“建档 / 初始化”，携带 `?softwareId=`。
- 技术节点详情新增“初始化 / 补充文档”，携带 `?nodeId=`；同时新增“文档体检”。
- 手动模式包含范围选择、模板选择、来源录入、链接检查、筛选、预览计数与逐项预览、确认勾选、执行结果。
- 自动模式包含规则创建、规则列表、启用 / 暂停、删除、最近运行状态、待处理项与手动处理入口。

## 9. Seed 边界

- Seed 仍只用于首次安装的内置领域和节点及其内置文档。
- 用户通过建档流程创建的节点、关联、文档写入数据库，不写回代码种子。
- 未修改 `server/services/tech-content-kubernetes.ts` 与 `tech-content-kubernetes-docs.ts`。

## 11. 未覆盖与限制

- PRD 在 `12.2 建档流程` 处截断，12.2 之后的条目未实现或未验收。
- “组合范围”按现有实现为先解析软件与节点候选，再按节点领域过滤并去重；未针对未提供的后续规则做扩展。
- 自动规则只覆盖已定义的两类创建触发；未提供定时任务、批量回填触发。
- URL 检查只验证 HTTPS 可达性，不代表技术结论正确；可达性结果不作为“已核实”依据。
- 预览哈希只绑定请求参数，不绑定数据库快照；执行时会重新解析候选，并依靠逐项事务与“不覆盖”条件保证安全。
