# 1. 项目定位与适用场景

本章帮助你判断 Opsite 是否适合你的工作方式，并解释它和通用监控平台、知识库、订阅工具的区别。

## 1.1 Opsite 是什么

Opsite 是一个**单用户、本地优先、可自托管**的个人运维情报与技术知识工作台。

它把两类通常分散在不同工具里的信息放在同一个本地应用中：

1. **外部情报**：你关注软件的版本发布、生命周期、安全公告、CISA KEV 实际利用信息，以及从 GitHub 和 CNCF 发现的新项目。
2. **个人理解**：你的技术雷达、技术地图、知识笔记、待研究问题和标准化技术文档。

数据默认保存在本机的 SQLite 数据库里，不依赖云端账号，也不要求你把笔记或软件清单上传到第三方服务。

> “本地优先”指的是默认部署和使用方式，不代表应用自带公网安全能力。Opsite 没有登录、角色和权限控制，默认只监听 `127.0.0.1`。

## 1.2 它解决什么问题

日常运维和技术选型中，常见的问题不是“没有信息”，而是信息太多且彼此割裂：

- 软件版本、EOL、漏洞和 KEV 信息散落在不同网站，难以和“我实际在用的版本”对上。
- 同一个漏洞会被多个来源重复推送，反复打扰。
- 技术雷达、评估结论、踩坑记录写在文档或聊天记录里，过一段时间找不到上下文。
- 想系统整理一个技术领域时，缺少可维护的树状结构和文档模板。

Opsite 的处理方式是：

- 每个软件只维护**一份身份信息**，版本、生命周期、公告和事件都关联到它。
- 同一条上游信号按去重键合并成**一个情报事件**，保留首次发现时间和上游发布时间。
- 关注、站内通知和邮件通知分开处理：站内通知先落库，邮件由后台队列独立发送。
- 技术地图用领域、技术树和架构视图组织知识；节点上可以记录掌握状态、关注级别、个人笔记和待研究问题。
- 知识建档只做确定性工作：套用固定模板、插入已知结构化信息、做规则检查，不生成 AI 技术结论。

## 1.3 适合谁

Opsite 适合：

- 需要长期跟踪一小批基础软件（如 Kubernetes、Docker、Nginx、MySQL、Redis）的个人运维或平台工程师。
- 想维护个人技术雷达、选型记录和技术地图的开发者。
- 希望数据留在本机、不想注册 SaaS 账号的用户。
- 愿意自己运行 Docker 或本地开发环境的用户。

它不适合：

- 需要多用户、角色、审批和审计的企业团队。
- 需要公网多租户访问或 SaaS 托管的场景。
- 需要自动生成技术方案、自动推断技术关系或自动撰写结论的场景。
- 需要浏览器 Web Push、移动端推送或跨设备同步的场景。

## 1.4 典型使用流程

一个常见的日常循环是：

1. 在“软件情报”中添加你关注的软件和当前使用版本。
2. 让采集任务同步版本、生命周期和漏洞数据。
3. 在“今日值班台”查看待处理信号，在“漏洞与修复”中确认本地影响并安排处理。
4. 在“情报事件”中把已处理的信号标记为已确认、已解决或已忽略。
5. 在“技术雷达”和“技术地图”中记录评估结论、学习状态和待研究问题。
6. 在“我的知识库”或技术节点里写下长期文档，必要时用“知识建档”初始化标准草稿。
7. 在“运行中心”检查数据源健康、采集失败和数据新鲜度。

## 1.5 核心概念

| 概念 | 含义 |
| --- | --- |
| 软件 | 你主动维护的软件条目，包含名称、分类、当前版本、使用状态和关注状态 |
| 公告（Advisory） | 来自 GitHub Advisory、NVD 等来源的安全公告；同一 CVE 可能对应多条来源记录 |
| 情报事件 | 按去重键合并后的主事件，是通知和处置的主要对象 |
| 本地版本影响 | 结合你填写的当前版本判断公告是否影响本地的结论；部分情况需要人工确认 |
| 生命周期 | 软件版本的 EOL、维护截止时间等信息，只采用可信来源提供的日期 |
| 关注 | 对软件、雷达条目、发现候选或单条公告建立订阅关系 |
| 技术领域 / 技术节点 | 技术地图中的一级领域和树状节点；节点可以关联软件、雷达条目和发现候选 |
| 知识建档 | 用固定模板为软件或技术节点初始化文档的辅助流程，不覆盖已有正文 |
| 数据源 / 采集任务 | 运行中心里的外部数据适配器和定时执行配置 |

## 1.6 与相邻工具的区别

- **不是监控系统**：Opsite 不采集主机指标、日志、链路或告警，也不替代 Prometheus、Grafana、Zabbix。
- **不是漏洞扫描器**：它不扫描你的主机或镜像，只汇总公开公告并结合你填写的版本做影响判断。
- **不是团队知识库**：没有多人协作、权限和评论；知识内容服务于个人。
- **不是 RSS 阅读器**：技术发现只从固定来源和启用规则中取候选，不做全网订阅。
- **不是 AI 写作工具**：知识建档不会生成技术结论，也不会自动修改文档状态。

## 1.7 安全边界（必读）

Opsite 是**无登录的单用户应用**：

- 能访问 API 的客户端会被视为可信用户。
- `/api/backup` 可以导出完整数据库，包含你的软件清单、笔记和设置。
- 默认监听 `127.0.0.1`；Docker 的宿主机端口默认也只绑定 `127.0.0.1`。
- 不要把 Opsite 直接暴露到公网。确需局域网访问时，至少使用防火墙限制来源，并在反向代理层增加认证和 TLS。

完整说明见 [SECURITY.md](../../SECURITY.md)。

## 1.8 当前版本与稳定性

当前版本为 `0.1.0`，仍处于早期阶段：

- 功能和接口可能变化。
- 数据库迁移尽量前向兼容，但升级前仍建议下载备份。
- 部分数据源适配器可能停用或受上游限流影响。
- 内置 Kubernetes、Prometheus 知识内容不会随采集结果自动修改。
