# 6. 版本与生命周期

“版本与生命周期”把软件的上游发布记录和维护周期放在一起，帮助你区分两件事：

- **有新版本**：上游发布了更新的版本号。
- **建议升级**：新版本是否兼容、是否仍在支持期内、是否值得现在升级。

Opsite 只负责呈现记录和计算版本先后，不会替你给出升级建议。

![版本与生命周期页面](../assets/screenshots/versions.png)

## 6.1 页面结构

页面顶部显示两类总数：

- “N 条版本记录”
- “N 个发布周期”

两个标签页：

| 标签页 | 内容 |
| --- | --- |
| 版本发布 | 各软件在 GitHub Releases、endoflife.date 等来源中的发布记录 |
| 生命周期 | 各软件的发布周期、EOL 日期、支持状态和最新补丁 |

## 6.2 版本发布

### 筛选

- **软件**：全部软件或指定软件。
- **通道**：全部通道、稳定版、预发布。
- **仅领先当前版本**：只显示版本号高于软件当前版本、且属于稳定版的记录。

右侧会显示“最新记录首次发现于……”，它指的是接口返回的第一条记录，不受当前筛选影响。

### 记录内容

每条记录包含：

- 软件 logo、版本号、软件名；
- 预发布徽标（上游标记为预发布时）；
- “领先当前 vX.Y.Z”徽标；
- 首次发现时间（本地首次入库）；
- 上游发布时间；
- 数据来源（GitHub Releases、endoflife.date）；
- 发布标题和说明摘要；
- “发布说明”外链。

“领先当前”只对稳定版判断。预发布版本即使版本号更大，也不会被标记为领先当前，避免把 RC 或 alpha 误认为应升级版本。

### 排序与分组

记录按上游发布日期倒序排列；没有发布日期的记录使用首次发现时间。页面按日期分组，组头显示日期和该组记录数；日期缺失时归入“发布日期未知”。

### 首次发现与上游发布

- **首次发现**：Opsite 第一次把这条记录写入本地数据库的时间。
- **上游发布**：上游来源给出的发布时间。

两者可能相差较大。首次同步时，历史版本会一次性入库，因此“首次发现”不能当作“刚刚发布”。

## 6.3 生命周期

### 顶部提示

生命周期标签页顶部可能显示：

- N 个软件已 EOL（已停止支持）；
- N 个即将到期（180 天内 EOL）；
- N 个生命周期未知（完全没有生命周期记录）。

### 默认显示规则

- 默认隐藏“非当前周期且已经 EOL”的历史周期。
- 勾选“包含已停止支持的周期”后显示全部。
- 如果筛选后没有可见周期，页面会显示前 4 条，避免空白。
- 记录较多时，可以“显示其余 N 个周期”或“收起历史周期”。

### 软件卡片

每个软件一张卡片，显示：

- 软件名和 logo；
- 当前版本，或“未配置”；
- 当前周期的支持状态，或“当前周期未匹配”；
- “查看详情”链接，跳到软件详情的生命周期标签。

表格列：

| 列 | 含义 |
| --- | --- |
| Cycle | 发布周期，例如 `1.32` |
| Released | 周期开始或发布日期 |
| Support | 支持状态 |
| EOL date | 停止支持日期 |
| Latest patch | 该周期的最新补丁版本 |
| 来源链接 | 上游生命周期来源 |

### 支持状态

| 标签 | 含义 |
| --- | --- |
| 支持中 | 当前日期早于 EOL，且不在 180 天预警范围内 |
| 即将停止支持 | 距离 EOL 不超过 180 天 |
| 已停止支持 | 已超过 EOL 日期 |
| 生命周期未知 | 没有可用的生命周期记录，或当前版本无法匹配周期 |

EOL 日期会显示为“已过期 N 天”“今天到期”“N 天后到期”或具体日期；上游没有公布时显示“未公布”。

## 6.4 数据来源与可信度

- 版本发布主要来自 GitHub Releases，部分来自 endoflife.date。
- EOL 日期只采用可信来源，不根据发布日期推算。
- 没有可靠来源的软件显示“未知”，不会猜测。
- 当前版本由你在软件配置中维护；Opsite 不会自动探测你实际运行的版本。

## 6.5 限制

- 版本发布一次最多加载 200 条，没有分页。
- 生命周期标签页没有软件筛选或搜索，只能滚动浏览。
- 生命周期记录没有手工编辑入口。
- 同一周期如果来自多个来源，页面可能显示多行；以来源链接为准，软件详情页会给出汇总判断。
- “有新版本”不代表兼容性、配置或升级路径已经验证。
